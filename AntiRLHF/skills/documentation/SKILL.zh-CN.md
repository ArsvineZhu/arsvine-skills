# 文档与作者口吻

遵守当前生效的 AntiRLHF 宪章和角色指令。修改前阅读原文。从文档与用户要求中确定谁在说话、谁会阅读、文章用来做什么、事实来自哪里。

## 站在正确的位置写作

- **作者的 README、文章或公告：** 以作者身份向读者表达。保留其判断、幽默、强调和第一人称。修改用户要求改变的部分，保留有个性的原文。不要加入一个代替作者说话的编辑、审阅者或助手。
- **产品/用户文档：** 面向实际用户，讲清能做什么、怎么做、会得到什么结果。
- **开发者文档：** 根据当前代码说明真实行为、契约、入口和扩展方法。
- **Agent 指令（`AGENTS.md`、`SKILL.md`、references）：** 直接指示执行者读取、修改、运行、保留或交付什么。例如写 `迁移调用方并删除旧适配器`，不要写 `本技能防止 Agent 发明适配器`。
- **研究档案：** 以项目研究者身份记录现场经历、文献结果与机制假设。把理论、命名和因果讨论写在研究主题内，而不是搬到操作指令中作免责声明。

编辑别人写的原文、翻译作品或为 Agent 编写指令时，读取 `references/author-and-audience.md`；其中包含 AntiRLHF README 作者身份被错误改写的原例。

## 完成可以直接使用的修改

阅读目标段落及上下文，理解修改后应表达的事实或行为。就地改写，保留无关内容，删除已经失效的文字。新增内容放在读者会寻找它的标题下，更新受文件移动影响的链接和项目实际维护的译本。

一项持续维护的事实或流程确定一个权威位置；其他文档链接到该位置。真正需要保存的迁移历史写在 Changelog 或研究档案中；当前用户指南直接描述现行系统。

具体纠错、凭空追加限定、局部要求扩散和真正不确定性的区别，见 `references/editing-and-prose.md`。创建/移动文档、更新导航，或在另一个仓库使用工具，见 `references/navigation-and-tools.md`。

## 检查写成的内容

按目标读者的身份通读完成段落。删掉自我表述、未经请求的作者来源声明、想象出来的反驳，以及紧跟明确结论的多余保留话语。影响实际含义或下一步行动的区别与未知事实应当保留。

对当前维护的 Markdown 和 AI 指令运行现有扫描器，再连同整段上下文处理发现：

```bash
python AntiRLHF/skills/documentation/scripts/check/governance_prose.py --changed
```

安装到 Codex 时，在使用方仓库运行 `$HOME/.codex/skills/documentation/scripts/check/governance_prose.py`。扫描器先使用项目配置，再查已安装配置，最后使用 Skill 自带配置。`block` 需要修正或针对具体表达给出有依据的豁免；`review` 与 `signal` 用于定位需结合语境阅读的内容。真正必要的技术区别即使命中规则，也应保留。

修改文档导航时，运行项目配置的 doc-graph 检查并实际跟随相关链接。以作者原定口吻交付最终文档。
