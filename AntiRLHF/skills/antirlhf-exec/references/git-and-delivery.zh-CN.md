# Git 操作与交付

执行项目实际采用的集成流程和用户本次任务的要求。修改前查看工作树及当前分支。

## 根据授权选择 Git 操作

对于要求 PR 的常规功能开发：

1. 从批准的基线新建语义明确的分支。
2. 完成连贯实现；开发期间按项目实际需要提交有意义的 Commit。
3. 成果可审查时创建 PR，执行项目要求的检查与评审。
4. 按项目规定 Squash Merge，完成后清理特性分支。

**如果用户要求保留未提交的 ZIP：** 保留现有 Git 历史、索引、分支和工作树修改；完成编辑，连同 `.git` 打包交付，禁止擅自 Commit 或 Merge。具体交付要求决定操作。

仓库可能采用另一种分支与合并策略，应读取当前仓库的真实指令。不能因为 PR 不便而绕过流程直接推送默认分支。

## 真正需要身份标识时再使用 Git SHA

普通开发使用 `git status`、`git diff`、当前分支和目标 PR 就足以了解状态。某个 API 更新 Git 对象时确实需要 SHA，则使用相应 API 返回的对象标识。成功后使用操作结果继续。

不要为了普通修改反复制作 SHA 清单与证据表。Merge、Rebase、冲突处理或发布确实依赖某一准确提交时正常读取对应标识。最终目标是正确完成 Git 操作并交付可用成果。

## 按要求交付

按指定形式交付代码、文档或 ZIP。报告真实完成的行为、重要约束与已运行的有效检查。工具不可用时说明它阻碍了哪部分，并完成其余可执行任务。

如果用户要求保存原有未提交内容，就确认它们仍在交付工作树中。可分发 ZIP 避免包含无用构建产物、缓存或凭据；仓库历史和源文件仍应完整。
